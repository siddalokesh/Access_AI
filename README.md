PROJECT: AI-Based WCAG Accessibility Linter

OVERVIEW:
This project is an accessibility testing tool that combines:
1. Gemini AI-based accessibility analysis.
2. Python rule-based accessibility checks using app2.py.
3. Playwright Chromium browser automation.
4. Flask dashboard for displaying results.

PROJECT STRUCTURE:

Accessibility_Project/
│
├── app1.py
│   ├── Flask dashboard
│   ├── Playwright browser automation
│   ├── Rendered HTML collection
│   ├── Original source collection
│   ├── Accessibility Tree / ARIA collection
│   ├── Computed styles collection
│   ├── Geometry collection
│   ├── Screenshot capture
│   ├── Gemini AI integration
│   ├── Findings merge and deduplication
│   └── Application startup
│
└── app2.py
    ├── Rule-based WCAG checks
    ├── Accessibility data inspection
    ├── Computed style checks
    ├── Geometry checks
    ├── WCAG checkpoint functions
    └── Script findings generation


WORKFLOW:

1. The user opens the Flask dashboard.
2. The user enters a webpage URL.
3. The user uploads a PDF screenshot.
4. The user clicks the Run Audit button.
5. app1.py receives the URL and PDF.
6. Playwright opens the URL in Chromium.
7. The webpage is rendered without modifying its DOM, CSS, or content.
8. The application collects:
   - Rendered HTML / DOM
   - Original page source
   - Accessibility Tree / ARIA data
   - Computed styles
   - Element geometry
   - Chromium screenshot
9. app2.py runs the programmed Python accessibility checks on the live page.
10. Gemini AI analyzes the collected webpage data and uploaded PDF.
11. AI findings and script findings are combined.
12. Duplicate findings are identified and merged.
13. The combined results are displayed in the existing dashboard.


APP1.PY RESPONSIBILITIES:

- Starts and manages the Flask application.
- Receives the URL and PDF from the dashboard.
- Opens the target webpage using Playwright.
- Collects rendered webpage information.
- Collects accessibility information.
- Collects computed styles and geometry.
- Captures a screenshot from Chromium.
- Sends webpage evidence to Gemini AI.
- Handles Gemini retries and fallback models.
- Combines AI and Python rule-based findings.
- Removes duplicate findings.
- Returns the final results to the dashboard.


APP2.PY RESPONSIBILITIES:

- Performs rule-based WCAG accessibility checks.
- Inspects the live Playwright page.
- Uses the rendered DOM.
- Uses the Accessibility Tree / ARIA information.
- Uses computed styles.
- Uses element geometry.
- Detects accessibility problems using Python functions.
- Returns script-based accessibility findings to app1.py.


DATA USED FOR RULE-BASED CHECKS:

1. Rendered DOM
   Used to inspect HTML elements, attributes, headings, links, forms, and images.

2. Accessibility Tree / ARIA
   Used to inspect roles, accessible names, states, and relationships.

3. Computed Styles
   Used to inspect actual browser styles such as colors, font sizes, visibility, borders, and focus indicators.

4. Geometry
   Used to inspect element position, width, height, size, and possible layout issues.


DATA USED FOR GEMINI AI:

1. Rendered DOM
2. Accessibility Tree / ARIA
3. Computed styles
4. Geometry
5. Chromium screenshot
6. Original page source
7. Uploaded PDF


FINDINGS SOURCES:

AI:
Findings generated by Gemini AI.

Script:
Findings generated by the programmed Python functions in app2.py.

AI + Script:
The same issue was detected by both Gemini AI and app2.py.


FINAL RESULT:

The application combines the AI findings and rule-based findings, removes duplicates, and displays the results in the existing Flask dashboard.

The dashboard design and the target webpage visual appearance are not changed. The modifications are made only to the backend data collection, accessibility analysis, and findings processing.
